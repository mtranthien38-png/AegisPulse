Quick “How it works”
First, check if the project is valid (the gate).
If it is valid, give a score from 0 to 5 for four things.

Three simple rules
Look at the real work: the code and the live app (if any live deployment). 
Start at 0. Add points only for things you can see.
Most projects will get a 1 or a 2. A 4 or a 5 is not common… like a Unicorn 🦄
Step 1: Check if the project is valid
Reject the project right away if any of these is true:
It has no real GenLayer contract, or the AI part does not run on GenLayer.
It uses the GenLayer name but does not really use a contract.
The code does not run.
It is empty, a copy of another project, or an example project with almost no changes.

A third decision: “request more info”
So far the doc had two outcomes: pass the gate and score it, or reject. Add a third one in the middle: 
request more info.
Reject ambiguity
A messy repo, an unclear way to run it, rough docs, a simple app, a common idea, a basic UI, or minor warnings can be a reason for reject. However, the line is thin and hard to define, I think here we have to trust our builder gut feeling to see if the project meets the bar for a GenLayer accepted project. Does it have potential? Is there clearly no “effort”?
Even if reject it’s important for the feedback to be very clear and well redacted for the user. As discussed on the channel, we need to educate. Unclear feedback leaves no room for progress. 
Reject or more info makes no sense if the feedback is unclear. 
Contract code must be in the repo
A Studio or deployment link on its own is not enough. If the code is not there to read, request more info. I’ll probably add the requirement of an explorer contract address or studio import contract on top of the contract code in the repository. Having the contract address to see activity as well as having a clear structure for us to easily review repositories is essential.
Verify, do not trust
Open the app and actually use it. Then check on the explorer that the deployed contract is the same one the builder submitted. This is essential and the main gate where AI assisted review fails. 
Use AI if you want but only where you can provide clear guidelines, when it comes to taste (use case potential, UI/UX, etc.) trust your human taste.
Always leave a note
As said before, a short line on what is missing or wrong is what helps the builder fix it. Think that the note you propose will be the one seen by the builder.
Many near-identical AI builds
Some builders mass-submit near-identical AI builds, one commit each, often broken. If the template used has no potential or scalability and is clear farming, reject. We want focused builders, not dispersed farmers.
Score higher for real use
Bump the score when GenLayer is essential, the use case is original, the contract logic is meaningful and well integrated, or there is 
real usage or traction.
 Do not let a nice UI carry a weak project. The GenLayer work matters more than how it looks.
Portal Update: Submissions Reopen, Zero Pending, and New Rules for Milestones &amp; Intelligent Contracts
Hey @Neurobuilder,
1. Submissions Are Officially Reopened
Over the past two weeks, we have been working through the entire review backlog, and today we have reached 
zero pending submissions
.
Every project, milestone, and contract in the queue has been reviewed. With that process completed, 
submissions are officially open again
.
Thank you for your patience during this period. This effort was not only about clearing the queue, but also about making the contribution pipeline more stable and scalable.
It gave us a clearer picture of what is actually being built in the ecosystem, allowing us to separate strong projects from the rest and prioritize use cases that create real value.
This reset was necessary, and the updated rules below are designed to build on that foundation.
2. Milestones: Now Reserved for Highlighted Projects
From now on, 
milestone submissions will only be available for highlighted projects
.
The reason is simple:
We want to focus our efforts on projects with proper use cases and real potential to be pushed toward the GenLayer community for actual adoption.
Previously, spreading milestone rewards across every accepted project resulted in too many low-impact builds receiving support instead of helping stronger projects move forward.
Over the coming week, we will review the pipeline of the most interesting projects from previous batches.
From that review, selected projects will become 
featured projects
, and these will be the projects actively promoted within the community.
If your project has real usage potential, the path forward is:
Get highlighted → Build through milestones → Grow within the ecosystem
3. Intelligent Contracts: A Reality Check
The acceptance rate for Intelligent Contract submissions has been around 
5%
.
That number reflects the quality and type of submissions we have been receiving.
What we are looking for are contracts that the community can actually reuse:
Useful primitives 
Reusable patterns 
Building blocks that other developers can integrate into their own projects 
What We Don't Want
We will not prioritize:
Contracts extracted from projects that were already submitted. This is considered the same work being counted twice. 
Small contracts created only to learn how consensus works. Learning is valuable, but a learning exercise is not considered a contribution. 
Minor variations of contracts that already exist within the ecosystem. 
To be direct:
We will be very strict with lightweight contracts.
The Intelligent Contract category should not be viewed as an easy way to earn points.
A contract must provide 
real value to the ecosystem
 to receive rewards.
If it would not be useful for another person building on GenLayer, then it is not ready for submission.
4. The Bar Is Going Up Everywhere
This is the common theme behind all these changes:
We are raising the standards across every part of the Portal to ensure that community effort turns into meaningful outcomes.
The focus is:
Fewer but better projects 
Milestones that push strong projects forward 
Contracts that other builders can reuse 
Remember, these updates build on top of the Project Submission Rules announced last week.
If you have not read that announcement yet, make sure to review it before submitting anything new:
📢
 
#builder-announcements
5. Final Message
Builders who are doing serious work have nothing to worry about.
If anything, these changes are designed to make sure that valuable contributions receive the attention and rewards they deserve.
Submissions are open.
Build something people will actually use. 
🚀
End of Update
